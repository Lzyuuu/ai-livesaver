# 生成参数按「全局默认 + 推理配置覆盖」继承

spec-v451(#53)要把温度、最大输出 Token、Top_P、采样预设（精准/均衡/创意）与指令模板暴露给用户调节。这些「生成参数」（定义见 `CONTEXT.md`）挂哪一层有三种选择：全局唯一一份；每份推理配置各自独立；全局默认 + 推理配置可覆盖。

决定采用**全局默认 + 推理配置覆盖**：Settings 的 AI & Models 维护一份全局默认，每份推理配置可对其逐项覆盖，未覆盖项继承全局默认。理由：任务间差异真实存在（聊天要创意、记忆整理要精准），纯全局无法表达；而纯 per-profile 让每个 Provider 重复配置同一组参数，成本高。该继承语义与 `CONTEXT.md` 既有「推理配置：未单独指定的任务继承默认配置」保持一致。

## Consequences

- 存储：全局默认存设置层；推理配置 record 增加可空覆盖字段（空 = 跟随默认）。
- 请求拼装（`ProviderConfig.kt` 的 payload 构建）按「覆盖优先、缺省继承全局」解析后再填 `temperature`/`max_tokens`/`top_p` 与指令模板头部。
- UI：推理配置编辑页对被覆盖项提供「跟随默认」态；AI & Models 页编辑全局默认。

## Considered Options

- **全局唯一**：实现最简，但无法表达「不同任务不同参数」，且与推理配置的继承语义冲突——拒绝。
- **每份推理配置独立**：表达力够，但重复配置成本高、无默认值兜底——拒绝。
