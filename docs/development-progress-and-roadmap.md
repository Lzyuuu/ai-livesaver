## 2. 产品定位与基础架构

AI Livesaver 是一个围绕用户运转的 AI 虚拟社交世界，而不是传统 AI 工具工作台。

当前技术与产品基础如下：

- 仅面向 Android。
- 使用 Kotlin、Jetpack Compose 与 Material Design 3。
- 最低支持 Android 9 / API 28，目标 API 36。
- 以 iQOO 15 Ultra 和骁龙平台为首要真机目标。
- 采用原生 Android 导航与系统返回语义。
- 通过 GitHub Releases 分发侧载 APK。
- 图片模型、模型文件与骁龙 NPU 生图加速由 Local Dream 管理；AI Livesaver 负责世界编排、队列、交互和内容归档。

## 3. 已完成的产品能力

### 3.1 世界入口与导航

主导航已经形成五个社会空间：

- **World**：欢迎入口、关系提醒、未读消息、近期帖子、世界事件和创作队列。
- **Chats**：用户与核心 AI 角色的私密关系空间。
- **Moments**：承担朋友圈、Instagram 与 X 式轻社交。
- **Commons**：承担 Reddit 式主题讨论与社区活动。
- **Me**：身份、设置、Provider、Local Dream、备份、隐私、诊断与更新入口。

World 保留用户需要优先回应的关系和事件，但整体表达为一个持续生活的世界，而不是任务面板。

### 3.2 AI 角色与关系

- 支持创建、编辑、停用、离开和删除角色。
- 支持 Character Card V2 JSON/PNG 导入。
- 支持核心角色、普通角色和 NPC 三种关注层级。
- NPC 可以随机参与社区活动，不要求用户维护。
- AI 角色之间允许有限互动，但世界仍以用户和角色关系为中心。
- 关系使用叙事标签、摘要和事件演变，不向用户暴露机械数值。
- 角色身份、认知、共同世界事实和用户上下文分层保存。
- 角色设定修改不会静默重写已经发生的历史。

### 3.3 Chats 与长期记忆

- Chats 已重构为关系优先的 Messenger 入口。
- 支持会话列表、角色搜索、角色管理、最近消息和特别关注标识。
- 支持“会话列表 → 私聊 → 返回列表”的明确导航层级。
- 从 World 或通知进入时仍可直达指定角色。
- 屏幕返回按钮与 Android 原生返回均可退出私聊。
- 消息编辑器固定在底部，支持多行输入。
- 消息历史独立滚动。
- 支持流式回复、失败重试、中断恢复和继续回复。
- 支持重新生成回复、查看生成来源和恢复历史版本。
- 支持从用户消息处改写时间线。
- 自动提取明确、耐久的长期记忆，不把短期闲聊全部保存。
- 每条记忆保留来源、生成时间和所属角色。
- 记忆允许用户编辑、删除和固定。

### 3.4 Moments 与 Commons

- 用户与 AI 角色都可以发布内容。
- Moments 支持轻量动态、图片、受众控制和 AI 回复控制。
- Commons 支持主题帖与多层讨论。
- 用户作为世界的完整成员参与内容与关系，而不是旁观者。
- NPC 可作为社区背景成员维持活跃感。
- AI 自动发布由独立活动设置与预算控制。

### 3.5 世界自动运行

- 支持自动生成世界事件与世界编年史。
- 支持用户离开后的事件补演。
- 补演基于离开时长和世界状态，不要求应用永久驻留后台。
- 世界活跃度和通知频率分开配置。
- 自动推理拥有独立预算，不影响用户主动聊天。
- 支持开机后恢复世界自动化。
- 支持持续世界服务和待处理任务恢复。
- 世界内容离线可读，网络恢复后可继续处理等待操作。
- 世界正文和生成图片不会被当作普通缓存随意清理。

### 3.6 BYOK Provider

- 首版支持 OpenAI-compatible 云端 Provider。
- 可配置 Base URL、API Key、模型和预设。
- 支持聊天、结构化生成和视觉理解能力检测。
- 支持为不同推理任务选择 Provider。
- 不进行无提示的静默切换；失败时明确显示实际错误。
- API Key 使用 Android Keystore 加密保存。
- 已为 DeepSeek 等兼容服务保留直接接入路径。

### 3.7 视觉理解

- 可独立配置视觉 Provider。
- 若未配置视觉 Provider，则尝试使用通用 Provider。
- 通用 Provider 不支持多模态时，可由视觉 Provider 先将图片转换为自然语言，再交给通用模型。
- 只有用户上传、且尚未包含可信媒体描述的图片会触发视觉理解。
- AI 自己生成且已经保留提示词与描述的图片不会重复调用视觉 Provider。

### 3.8 Local Dream 与图片

已经实现 Local Dream 伴生应用集成层：

- Local Dream 可用性探测。
- SSE 生图进度解析。
- RGB 结果解码和本地图片保存。
- 生图队列、暂停、恢复和失败状态。
- Local Dream 参数导入。
- 应用恢复或 Local Dream 恢复后继续处理队列。
- 用户可以导入 Local Dream 已生成图片及其提示词参数。
- 提示词可用于生成媒体描述。
- 图片单击放大。
- 放大状态可直接打开操作菜单。
- 再次点击图片或使用 Android 原生返回可退出预览。
- 支持直接重新生图。
- 支持修改提示词后重新生图，编辑框为多行输入。
- 支持图片版本历史和旧版本恢复。

真实 iQOO 设备上的 Local Dream 握手、骁龙 NPU 推理、长任务恢复仍需验收。

### 3.9 隐私、备份与数据控制

- 不采集遥测或分析数据。
- 仅按具体操作请求 Android 权限。
- Provider 凭据使用 Android Keystore 加密。
- 世界备份不包含 Provider 凭据。
- 支持本地世界导出与恢复。
- 更新前提供备份提示。
- 世界重建与彻底删除数据为两个独立操作。
- 通知内容以隐私和关系提醒为原则。
- 支持查看诊断信息，但不自动上传。

### 3.10 更新与发布

- 已实现 GitHub Releases 在线更新检查。

## 6. 动效与交互审查

| Before | After | Why |
| --- | --- | --- |
| Chats 自动进入第一个角色 | 使用明确的会话列表进入私聊，并由返回键回到列表 | 高影响：恢复清晰空间层级，避免用户失去位置感 |

审查结论：**Approve**。当前没有阻止 `m109` 发布的动效问题。

## 7. 稳定版前的主要风险

### 7.1 iQOO 15 Ultra 真机

- Android 16 与 120 Hz 滚动、触控反馈。
- 软键盘遮挡、多行输入和长对话。
- 大字体、深浅色和减少动画。
- 系统返回与预测性返回。
- OEM 后台限制、进程回收与恢复。

### 7.2 Local Dream 真机闭环

- AI Livesaver 与 Local Dream 的真实握手。
- 骁龙 NPU 实际生成图片。
- SSE 进度、结果返回与保存。
- Local Dream 未启动、被杀死或异常返回时的处理。
- 应用重启后的队列恢复。
- 重新生图、提示词修改和图片版本恢复。

### 7.3 真实 Provider

- DeepSeek 等真实 OpenAI-compatible Provider 的流式聊天。
- API Key 错误、超时、断网、限流和服务端异常。
- 结构化输出不完整或畸形时的安全处理。
- 独立视觉 Provider。
- 多模态与非多模态通用 Provider 的分流。

### 7.4 后台世界

- iQOO 电池策略下的持续世界服务。
- WorkManager、开机恢复和进程重建。
- 离开时长补演的规模与合理性。
- 通知频率、隐私内容与点击跳转。

### 7.5 数据可靠性

- 大型世界备份与恢复。
- 版本升级和数据库迁移。
- 聊天、生图、恢复过程中的进程死亡。
- 世界重建与彻底删除的边界。
- 异常模型输出对现有世界数据的影响。

## 9. 稳定版之后的路线图

以下能力明确延后，避免影响首版收敛：

- Hugging Face 模型仓库浏览与下载。
- 本地文本模型推理。
- 直接面向 Snapdragon NPU 的文本模型运行时。
- 语音输入、语音通话与 TTS。
- 群聊。
- 小游戏和更复杂的 AI 角色间活动。
- 非 OpenAI-compatible Provider 专有协议。

## 10. 下一步执行原则

在完成 M110 真机验收前，不再增加大型功能。后续工作按以下顺序处理：

1. 真机阻塞问题。
2. Local Dream 与真实 Provider 端到端缺陷。
3. 数据安全、升级和恢复缺陷。
4. 无障碍与交互一致性。
5. 稳定版发布。

这一顺序能够最快暴露模拟器无法发现的问题，也能避免在基础集成尚未通过时继续累积 UI 和功能债务。
