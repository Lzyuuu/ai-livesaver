# AI Livesaver 0.1.0-m111

- 使用仓库 `.env` 提供的真实 LLM Provider 完成全部 AI 路径验收：能力鉴定、Messenger 单聊/群聊、Binder 结构化生成、Ustagram / Rebbit / Y 生成均通过真实 Provider，并校验 Provider/model provenance。
- 生产 Binder 编排（`BinderOrchestrator`）要求至少两个候选：单候选响应立即失败且不推进草稿；外层 envelope 或内层候选 JSON 截断各最多自动重试一次，无效结果不落库。
- Messenger 群聊编排（`MessengerGroupOrchestrator`）统一负责群成员 pending 回复、群 prompt、成员归属与持久化；失败重试保持同一消息时间线。
- Provider 结构化请求针对 DeepSeek 端点/模型自动关闭 thinking（含 Custom 保存方式）；结构化格式错误仅重试一次，空白与 `...` 输出不重试且不产生帖子/预算/ provenance。
- 社交生成失败或空白时不写入模板内容；Ustagram、Rebbit、Y 真实内容均带 Provider/model provenance。
- API 28 修复本地 HTTP 测试服务器未消费请求体导致的连接重置竞态；API 28 社交路径复用现有 WorldStore，避免并行 SQLite helper 问题。
- 修复并补齐双设备 instrumentation 证据：API 28 / API 36 各 73 项测试，69 PASS / 4 条件 SKIP / 0 FAIL，其中 2 项真实 Provider 测试 2 PASS / 0 SKIP / 0 FAIL。

验证：`testDebugUnitTest`、`lintDebug`、`assembleDebug`、`assembleDebugAndroidTest`、`connectedDebugAndroidTest`（API 28 / API 36）、`assembleRelease` 通过。
